# ForCats — КР №3

Тема: «Адаптивная вёрстка и доступность многостраничного HTML/CSS-сайта».

Проект основан на собственной КР №1 `kr1-html-css-shop`; оригинальный дизайн и товары сохранены. Bootstrap не используется.

## Страницы
- `index.html` — главная.
- `catalog.html` — каталог и фильтры.
- `product.html` — товар, характеристики и форма.
- `order.html` — учебная форма заявки.
- `contacts.html` — контакты.
- `about.html` — о магазине (дополнительная страница).

## Адаптивные решения
- `css/style.css` — исходный стиль магазина.
- `css/responsive.css` — адаптивная вёрстка поверх исходных стилей.
- Медиазапросы до 1023, 767 и 479 px; сетки карточек переходят с 3 колонок на 2 и 1.
- Каталог на узких экранах размещает фильтры над товарами.
- Страница товара превращается в одну колонку.
- Навигация переносится по строкам, интерактивные ссылки имеют увеличенную область нажатия.
- Таблица характеристик прокручивается по горизонтали без переполнения экрана.
- Формы, модальное окно и чат адаптированы к ширине телефона.

## Доступность
- Добавлена ссылка пропуска навигации «Перейти к содержимому».
- Текущая страница обозначена `aria-current=page` там, где уже была активная ссылка.
- Видимый `:focus-visible` для управления клавиатурой.
- Прокручиваемая таблица доступна для фокуса с клавиатуры.
- У изображений каталога заменены общие подписи вида «Товар 1» на осмысленные.
- Для уменьшения анимаций поддерживается `prefers-reduced-motion`.
- На отдельной странице заявки поля связаны с `label`, есть `required`, статус выводится через `textContent`.

## Самостоятельные доработки
Сохранены исходные дополнительные страницы «О нас», чат и визуальный стиль. Добавлены доступная ссылка пропуска навигации, адаптация плавающего чата, прокручиваемые таблицы и отдельная адаптивная страница заявки.

## Запуск и проверка
Открыть `index.html` в браузере. Проверить страницы при ширине 375, 768 и 1280 px, поиск фокуса клавишей Tab, прокрутку таблицы и заполнение формы.

### Lighthouse — сохранённые исходные проверки

В каталоге `lighthouse/` находятся **реальные HTML-отчёты**, сохранённые после проверки сайта в Chrome 31.10.2026 (до исправления контрастности):

| Страница | Performance | Accessibility | Best Practices | SEO |
| --- | ---: | ---: | ---: | ---: |
| `index.html` | 100 | 95 | 100 | 91 |
| `catalog.html` | 100 | 96 | 100 | 100 |
| `order.html` | 100 | 96 | 100 | 100 |

По отчётам найдены нарушения контрастности у розовых кнопок, ссылки «Главная», зелёного бейджа «Новинка» и кнопки «применить» на светло-розовом фоне. На главной странице отсутствовало `meta name="description"`.

**Исправления после аудита:**
- цвет интерактивных элементов в `css/style.css`: `--color-primary: #b12c77` вместо `#dc5ea6` (контраст с белым примерно 6.01:1; со светло-розовым `#fff5fa` примерно 5.63:1);
- прежний розовый `#dc5ea6` сохранён у логотипа через `--color-brand-pink`, чтобы не менять оформление шапки;
- бейдж «Новинка» получил фон `#147a2a` вместо `#168a2f` (контраст с белым примерно 5.46:1);
- в `index.html` добавлено собственное метаописание и более конкретный `title`.

**Важно:** приложенные HTML-отчёты — исходные замеры, а не «после исправлений». После замены файлов нужно повторить Lighthouse на `index.html`, `catalog.html`, `order.html` и сохранить новые отчёты, например `index-report-after.html`, `catalog-report-after.html`, `order-report-after.html`. Баллы до повторной проверки не заявляются.

Для сдачи создать отдельный GitHub-репозиторий `kr3-responsive-shop` и загрузить содержимое папки.

## дополнения
На странице товара добавлены демонстрационные отзывы и форма добавления отзыва с оценкой; новые отзывы сохраняются локально в браузере (localStorage). На странице заявки доступны выбор товара и количества, способ получения, промокоды MEOW10 (10%) и KITTY15 (15%), пересчёт суммы и проверка формы. Сервер и платёжная система не подключены; данные не отправляются.


## Дополнительная переработка адаптивности

- Сворачиваемое меню на ширинах до 767 px: кнопка «меню», `aria-expanded`, закрытие по Escape и нажатию вне меню. На планшетах навигация переносится на отдельную строку с удобными промежутками.
- Отступы по краям задаются через `--page-gutter` и `clamp()`, отдельно для телефонов, планшетов и больших экранов.
- `srcset` и `sizes` у фотографий товаров и главного изображения. В `images/responsive/` лежат настоящие WebP-версии разной ширины (320, 640, 960 px); браузер выбирает нужную.
- Сетка карточек, каталог, форма заказа, таблица и отзывы адаптированы для узких экранов.
- Для ручной проверки в DevTools используйте ширины 360, 430, 768, 1024 и 1440 px; после открытия каждой страницы убедитесь, что нет горизонтальной прокрутки документа.
- В `lighthouse/` сохранены исходные отчёты для `index.html`, `catalog.html`, `order.html`; после исправления контрастности необходимо повторить аудит и добавить отчёты «после».

## выполнение по практическим занятиям №12–14

### практика №12 — адаптивная вёрстка

- подключён `css/responsive.css` после `css/style.css` на каждой странице; добавлены гибкие размеры, `clamp()` для шрифтов и отступов;
- сетка товаров построена по принципу Mobile First: 1 колонка по умолчанию, 2 от 480px, 3 от 1024px;
- адаптированы шапка, меню, hero-блок, каталог с фильтром, карточки, формы и таблица;
- подготовлены WebP-изображения с `srcset` и `sizes`;
- контрольные ширины для ручной проверки: 360, 430, 768, 1024, 1440px.

### практика №13 — аудит доступности

- проверены семантические теги, основной `h1` и `main`, `skip-link`, `aria-current`, `alt`, `label` и клавиатурный фокус;
- мобильная таблица характеристик дополнительно оформлена карточками, заголовки строк заданы через `th scope="row"`;
- сохранена доступная кнопка меню с `aria-expanded`, закрытием по Escape и закрытием по нажатию вне меню;
- в `lighthouse/` сохранены три настоящих отчёта Chrome; найдены и исправлены нарушения контрастности и отсутствующее метаописание главной; повторная проверка выполняется после обновления сайта.

### практика №14 — подготовка к сдаче

- проверьте все страницы на пяти указанных ширинах в Chrome DevTools;
- проверьте картинки во вкладке Network → Img и клавиатурную навигацию;
- повторите Lighthouse Accessibility для главной страницы, каталога и формы заказа, сохраните отчёты «после» вместе с исходными;
- создайте отдельные Git-ветки/коммиты и Pull Request по методичке (действия на GitHub выполняются вручную);
- отправьте ссылку на итоговый репозиторий `kr3-responsive-shop` в СДО.

### что выполнено сверх базовых требований

- компактное сворачиваемое мобильное меню;
- мобильное карточное представление характеристик вместо горизонтальной прокрутки;
- WebP в нескольких разрешениях, адаптивная типографика, форма отзывов и промокоды.

**примечание:** реальный аудит Lighthouse, публикация GitHub Pages, Git-история и Pull Request не имитируются. ФИО и группу необходимо заполнить перед сдачей.
